## 1. 目标与范围

老师和学生基于已有单篇作文报告，查看多篇的成绩趋势、分项均分及基于分数的数据总览。跨篇聚合是本次新增，不等于同一篇作文的多轮修改。不重新评分，不把首末分差解释为教学效果或能力提升率。

教师后台与学生 iPad 均展示；不制作学情分析新页面，不新增一级业务菜单。学生管理下独立“練習情況”菜单中的新增分析操作此前暂停，当前不宣称已完成。

## 2. 页面与入口（最新确认）

1. 后台：學生管理 → 學生列表 → 詳情 → 學習任務或練習情況 → 命題作文 → **個人綜合報告**。
2. 学生详情只保留原“學習任務／練習情況”两个主页签。命题作文列表上方提供分析按钮，不将跨篇分析重复放到每篇操作，不在学生列表新增分析列。
3. 点击进入独立分析视图，保留学生资料，默认直接显示结果；无需选篇、点击生成或切换“作文列表／分析報告”。删除“自動匯總已有有效作文報告，查看表現變化與原文依據。”整行。
4. 面包屑到当前末级：**學生管理 / 學生列表 / 學生詳情 / 個人綜合報告**。学生列表可返回列表；学生详情可返回原详情，保留原主页签及作文分类。顶层學生管理是菜单分组，不虚构落地页面。
5. iPad：保留个人概览的“學習報告”入口，直接打开“個人綜合報告”，不展示“綜合表現／個人綜合報告”切换及原有综合学习数据占位页面；自主学习写作区提供同一报告快捷入口。本次仅收敛原型展示范围，不定义正式产品删除原有综合学习报告。顶部“教師後台／iPad 平板端”是原型演示切换，不属于正式产品菜单。
6. 当前独立视图使用组件状态，尚未实现独立可分享 URL 和刷新恢复分析视图；见 D06。

个人综合报告两端展示顺序：学生资料／统计周期 → 数据总览 → 指标卡 → 得分图表与维度。数据总览使用既有确定性统计；单篇说明无法比较变化，零篇不生成总览正文。

## 4. 数据规则与模板

| 模块 | 数据来源 | 当前原型与正式规则 |
|---|---|---|
| 学生资料 | 原学生列表/详情 | 姓名、账号、年级、班级；原型使用虚构自然姓名，已配置32名学生的独立报告与跨篇分析（2026-10-09更新） |
| 有效报告 | 单篇报告状态、作文/报告标识 | 当前筛选可用、有数值总分且有量表的4篇；历史70分报告缺量表被排除，正式是否只纳入总分待D02确认 |
| 总分/维度 | 最终有效单篇评分 | 该样例四维满分40/30/20/10；直接沿用原分，不重新按旧PRD反推权重 |
| 平均得分 | 有效总分求和÷有效篇数 | 65、69、73、78 → 71.25，展示71.3；不得将未提交计0 |
| 分差/时间 | 最早与最近有效报告 | 78−65=+13；日期按提交时间，重批版本及同日排序待D03确认 |
| 各维度平均分 | 有该维度的报告独立聚合 | 均值28.25/21.5/14.25/7.25；各自除以40/30/20/10算得分率；页面仅显示维度名、平均分/满分及进度条，不常驻显示百分比与样本数 |
| 数据总览 | 最终有效评分、提交时间、量表 | 使用确定性公式和模板生成，不调用AI；不同评分标准不混合，缺分项不补0，不推断原因 |
| 疑似错别字 | OCR疑似识别标记 | 不能当作学生确定写错的数量，更不能冒充错误率 |
| 来源 | 任务/自主练习关联 | 原型映射未获接口证明；取消界面来源筛选不代表已验证合并范围，见D01 |

同一篇多稿不得直接当多篇增长；有效版本、去重、教师改分更新需业务和研发确认。任务完成与报告可用不是同一个状态。

## 源数据约束与功能验收

当前页面保留基础统计、逐篇得分趋势、分项均分及数据总览；报告可从趋势节点进入。评语汇整、训练建议及写作足迹列表不在当前页面范围。

数据总览示例：5篇得分85、87、89、91、82，平均86.8；首篇85、最近82，较上次下降9。四维均分33.4/40、25.4/30、18.4/20、9.6/10，按未取整得分率比较，内容83.5%最低。仅描述分数事实，不宣称能力退步。验收状态：待验收。

边界：0篇不生成概括；1篇不比较变化；分项有效0保留；缺任何分项时不输出跨维度最低结论；并列最低全部列出；所有维度相同则说明持平。总分均值与得分率最多显示1位小数。原始分数不回写。

用户已确认原文、批注和版本数据可用；跨篇AI分析仍在方案讨论，不纳入本期实现。接口具体字段、原稿/AI改稿标识、有效版本选择、定位方式及权限仍需研发对接验证，不再将数据是否存在列为待确认。
